# falcon-signer

A command-line signer for the Falcon accounts in this repository, built on PQClean's
Falcon-512 through the [`pqcrypto-falcon`](https://crates.io/crates/pqcrypto-falcon)
bindings. PQClean signs with the Falcon round-3 hash-to-point, SHAKE-256 over
`nonce || message`, which is what the accounts verify; the signer converts PQClean's byte
encodings into the accounts' felt layout.

```bash
cargo build --release          # binary: target/release/falcon-signer

falcon-signer keygen --out key.json
falcon-signer public-key --key key.json
falcon-signer sign --key key.json --hash 0x<transaction hash>            # hint account
falcon-signer sign --key key.json --hash 0x<transaction hash> --direct   # direct account
```

Every command prints JSON:

- `keygen` and `public-key`: `{"public_key": [29 felts]}`, the NTT-domain public key that
  both accounts' constructors take.
- `sign`: `{"signature": [60 or 31 felts], "blocks": 8 or 9}`. The signature is packed
  `s1` (29 felts), the 40-byte salt as two felts of 20 little-endian bytes, and, for the
  hint account, packed `s1 * h` (29 felts). The signed message is the transaction hash as
  32 little-endian bytes. `blocks` is the number of SHAKE-256 blocks the on-chain
  hash-to-point consumes; a 9-block signature costs about 4.07M more L2 gas to verify.

## What is checked

Before `sign` prints a signature it is verified twice: by PQClean's own verifier, and
against the equations the contract evaluates (the hint check in the NTT domain, then the
norm bound), using the NTT evaluation points generated by `scripts/gen_ntt_tables.py`.
Decoding follows PQClean's canonicality rules: a wrong header, a public-key coefficient at
or above q, a "-0" or oversized signature coefficient, non-zero padding bits and trailing
bytes are all rejected.

`scripts/gen_pqclean_vectors.py` uses this signer to write
`crates/falcon_512/tests/pqclean_interop.cairo`, so CI checks on every run that the Cairo
verifiers accept PQClean signatures, covering both hash-to-point lengths, and reject them
over another hash.

## Key handling

`keygen` writes the PQClean public and secret key bytes as hex in a JSON file. It never
overwrites an existing file and creates it readable by its owner only, but the secret key is
stored unencrypted: this is a reference tool for development and testing, not a wallet.
PQClean's `clean` Falcon implementation is constant-time, unlike falcon.py, which the repository's
fixtures use. A production wallet should keep the secret key in an encrypted store or a
hardware module and reuse this crate's encoding.

The signer has not been independently audited.
